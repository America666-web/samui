SiteMarket — демо-магазин готовых сайтов (без сервера)
========================================================

ЗАПУСК
------
Просто откройте index.html в браузере (двойной клик). Все данные хранятся
в localStorage браузера — ничего не отправляется на сервер, кроме фото,
которые вы явно загружаете (см. ниже про imgbb).

ВХОД АДМИНИСТРАТОРА
--------------------
На странице login.html введите:
  Логин:  fortter
  Пароль: 4205
Это откроет админ-панель (admin.html).

ЧТО НОВОГО В ЭТОЙ ВЕРСИИ
--------------------------
1. Товар БЕЗ загруженного файла сайта (ссылки или HTML-кода) не появляется
   в публичном каталоге вообще — покупатель его не видит. Из 6 стартовых
   товаров сейчас "живые" только два («Кофейня» и «Портфолио фотографа»),
   остальные четыре лежат в админке как черновики без файла — так и
   задумано, чтобы было на чём потестировать сценарий.

2. Кнопка «Просмотр» на карточке открывает РЕАЛЬНЫЙ сайт во встроенном
   окне (iframe), а не картинку. Поверх него — водяной знак
   "SITEMARKET · ПРЕДПРОСМОТР", который генерируется JS-ом поверх iframe
   (не часть самого сайта) и виден только в режиме предпросмотра.

3. Хранение файла сайта — на выбор администратора при добавлении товара:
     - «Ссылка» (рекомендуется) — сайт хостится где угодно отдельно
       (например, GitHub Pages), у нас хранится только URL. Место в
       базе почти не расходуется.
     - «HTML-код» — для маленьких демо-страниц: вставленный HTML
       сжимается (LZString) и дополнительно кодируется простым
       XOR-шифром с ключом, зашитым в коде (js/sitecrypt.js), затем
       превращается в одну base64-строку и лежит в объекте товара.
       Расшифровать её может только код сайта — у случайного человека,
       который откроет localStorage через DevTools, будет просто набор
       символов, а не читаемый HTML.
     - «Без файла» — товар остаётся черновиком в админке, в витрину
       не попадает.

ЧЕСТНО О ГРАНИЦАХ ЭТОГО ПОДХОДА
----------------------------------
XOR-кодирование и водяной знак — это не крипто-защита в полном смысле:
   - Ключ шифра лежит в JS-коде, который выполняется в браузере
     пользователя, — значит его можно найти и написать свой
     расшифровщик. Это ЗАТРУДНЯЕТ копирование, а не делает его
     невозможным технически.
   - Водяной знак наложен через CSS/JS поверх iframe — его можно убрать
     через DevTools, если очень хочется. Он защищает от случайного
     "просто сохранил страницу", а не от целенаправленного взлома.
   - Единственный способ ПОЛНОСТЬЮ исключить копирование содержимого —
     не отдавать его браузеру пользователя вообще (например, показывать
     сайт через видео-стрим удалённого браузера). Для статического
     сайта без сервера это нереализуемо.

ЧТО УМЕЕТ АДМИН-ПАНЕЛЬ
-----------------------

Вкладка «Каталог сайтов»:
  - Добавление нового товара: название, категория, цена, краткое и
    подробное описание, фото (загружается на imgbb, см. ниже).
  - Подробное описание показывается покупателю в окне «Просмотр» —
    чтобы человек не покупал сайт вслепую.
  - Удаление товаров.

Вкладка «Пользователи»:
  - Список всех зарегистрированных пользователей: внутренний ID (#uid),
    имя, email, баланс, число покупок, статус.
  - Кнопка «+ Баланс» — начислить пользователю виртуальные рубли
    (в этом демо покупка списывает деньги именно с этого баланса,
    так как подключать настоящий платёжный шлюз без сервера нельзя).
  - Кнопка «Забанить/Разбанить» — заблокированный пользователь не
    сможет войти в свой аккаунт.

ФОТО И ХРАНЕНИЕ ИЗОБРАЖЕНИЙ
----------------------------
Картинки (фото сайта в каталоге, аватар пользователя) НЕ хранятся
локально в открытом виде. При выборе файла он сразу загружается на
внешний хостинг imgbb, а в базе (localStorage) остаётся только ссылка
на изображение. Использован API-ключ imgbb, который в коде хранится
в закодированном (base64) виде — это не «военная» защита, а просто
исключает хранение ключа открытым текстом в файле.

ЛИЧНЫЙ КАБИНЕТ ПОЛЬЗОВАТЕЛЯ
-----------------------------
  - Смена имени и аватарки (фото загружается через imgbb).
  - Смена пароля (требует ввода текущего пароля).
  - Просмотр баланса и внутреннего ID (#uid).
  - Список купленных сайтов.
  - Кнопка «Наполнить своими данными» на купленном сайте — пользователь
    вводит название компании/имя, телефон и короткое описание, и видит
    условный предпросмотр «своего» сайта с этими данными. Это учебная
    демонстрация идеи персонализации шаблона, без реального хостинга
    отдельного сайта под пользователя.

БЕЗОПАСНОСТЬ — ЧЕСТНО О ГРАНИЦАХ
----------------------------------
Это статический сайт без бэкенда. Любой такой сайт технически можно
открыть через "Просмотр кода страницы" или инструменты разработчика —
так устроены браузеры, и обойти это средствами HTML/CSS/JS невозможно.
В проекте есть несколько мер, которые сделаны честно как ОТПУГИВАНИЕ,
а не как надёжная защита:
  - блокировка правого клика и горячих клавиш разработчика (F12,
    Ctrl+Shift+I/J/C, Ctrl+U, Ctrl+S);
  - пароль администратора и ключ imgbb закодированы в base64, а не
    лежат в коде открытым текстом;
  - простое хэширование паролей пользователей (не для продакшена);
  - ограничение на количество неудачных попыток входа (5 попыток →
    блокировка формы на 30 секунд);
  - проверка на бан при каждом входе и при открытии личного кабинета.

Если нужна настоящая защита данных, аккаунтов и оплаты — необходим
реальный сервер с базой данных и платёжным шлюзом; такой формат
(«сайт без сервера») этого технически не может дать.

СТРУКТУРА ПРОЕКТА
------------------
index.html    — витрина с каталогом и превью товара
login.html    — вход (в т.ч. скрытый вход администратора)
register.html — регистрация
profile.html  — личный кабинет пользователя
admin.html    — админ-панель (каталог + пользователи)
css/style.css — все стили
js/storage.js — работа с localStorage (пользователи, товары, сессия)
js/auth.js    — регистрация/вход/смена профиля/защита от брутфорса
js/upload.js  — загрузка фото на imgbb
js/sitecrypt.js — сжатие и кодирование HTML купленных/демо-сайтов
js/app.js     — рендер каталога, превью товара (с водяным знаком), покупка
js/admin.js   — админ-панель
js/profile.js — личный кабинет

Примечание: index.html и admin.html подключают библиотеку lz-string с
cdnjs.cloudflare.com — нужен интернет при первом открытии страницы.
assets/       — логотип и баннер
data/demo.json— резервная копия стартового каталога (для справки)
